# Migrate to Vimcord 5 and Mongoose plugin 2

Follow these steps against application source, configuration factories, and shared UI helpers. This guide covers the stacked simplification commits from `main` through the fifth pass. Breaking APIs have no compatibility aliases. Package versions and the plugin peer range are updated separately when these releases are published.

## Check silent changes first

TypeScript cannot reliably catch these in JavaScript, loose objects, template strings, or configuration loaded from disk:

- Status names containing `$GUILD_COUNT`, `$USER_COUNT`, `$INVITE`, or `$STAFF_GUILD_MEMBER_COUNT` display those strings literally. Embed tokens are also literal now.
- `sendMethod` is not read. Delivery is inferred from the target unless `method` overrides it; an old explicit edit may become a reply, and an old follow-up may edit the original interaction response.
- `participants: []` permits nobody. Use `"anyone"` for open access. Omitted participants infer a human trigger or throw for a guild message with no trigger; replies to bot messages fail before sending.
- Participant IDs are fixed at creation. Non-participants are rejected on every custom ID, including IDs without a handler. Mutating an input array does not change access.
- A failed interaction deferral no longer logs command usage, because the handler was never reached. Handle it through onError and ordinary error logging.
- Unknown `access` keys log one warning per command or subcommand at construction, then remain ignored. The warning names the keys, identifies access open to everyone when no recognized grant is configured, and recommends `access: { users: [...] }` for `botOwner`. `access: { botOwner: true }` alone has no recognized grants, so all non-bot users passing hard restrictions are allowed. Replace it with `access: { users: [OWNER_ID] }`. If recognized grants are also present, only those apply: an owner who previously relied on the owner grant can lose access. An old nested `permissions` object is ignored entirely, which can also open a command.
- New default cleanup disables collector components. New default idle is 60 seconds without an accepted click. Prompt selection highlighting defaults false, and all extra buttons resolve immediately.
- Status streamUrl, old hooks/conditions, deployment wrappers, removed logging settings, and unsupported plugin options are ignored in untyped objects. Perform the searches below even if compilation succeeds.

Before running commands against Discord or MongoDB, use a test bot and a disposable database. The verification examples below type-check source; behavioral checks refer to that development environment.

## Client construction and startup

Find: `rg "new Vimcord|\.configure\(|\.use\(|plugins\.load|modules\.load|commands\.mount|commands\.unmount|importFrom" src`

Before:

```diff
- const client = new Vimcord({ client: { intents }, globals: { app: { name: "Bot" } } });
- client.configure({ app: { devMode: true } }).use(database);
- await client.plugins.load();
- await client.modules.load(imports);
- client.modules.commands.mount({ prefixes: ["!"] });
- await client.login();
```

After:

```ts
import { Vimcord } from "vimcord";
const client = new Vimcord({ intents, name: "Bot", devMode: true, plugins: [database], modules: imports, prefix: "!" });
await client.login();
```

Flatten Discord.js options and app settings. Put plugins, module imports, command hooks, and prefix routing in the constructor. `login()` owns all startup; remove manual lifecycle calls and per-manager importFrom. `prefix` accepts a string, strings, or a sync/async resolver returning those or null. Missing plugin dependencies and cycles now fail during construction. Plugins stay registered after unload, supporting failed-login retries. Use destroy to release the singleton before creating another client.

Verify: `pnpm tsc --noEmit`; boot once with development credentials and confirm modules and listeners load only once.

## Environment rules and gates

Find: `rg "deployment|conditions|preExecute|postExecute|onDeploymentTestFail|onConditionTestFail|onPermissionTestFail|onUnknownRoute|onSingleInvocation|permissionTestResult|conditionTestResult|deploymentTestResult" src`

Before:

```diff
- deployment: { environment: "development" },
- conditions: [checkFeature],
- hooks: { preExecute(ctx, next) { if (featureEnabled) next(); }, onPermissionTestFail(ctx) { report(ctx.permissionTestResult); } }
```

After:

```ts
import { PrefixCommandModule } from "vimcord";
const command = new PrefixCommandModule({
    name: "debug", environment: "development",
    hooks: {
        before: () => featureEnabled,
        onBlocked({ client }, block) { if (block.kind === "permission") client.logger.warn(block.reason); },
        onError({ client, error }) { client.logger.error("Failed", error); }
    },
    execute() {}
});
```

Replace conditions and preExecute with a before callback returning true to continue. It has no next callback. Move postExecute work into the handler with try/finally. Replace specialized failure hooks with onBlocked and its environment/permission/running/unknownRoute discriminator. Read failure details from block, not removed context result fields. Command hooks no longer carry an args tuple; read the typed invocation fields instead (event hooks still have their event args). A missing onBlocked forwards reasoned blocks to onError; other blocks are silent. Without onError, handler errors log.

Verify: `pnpm tsc --noEmit`; confirm a false gate blocks the handler, a true gate runs it, and the intended error response is sent.

## Slash routes and deferral

Find: `rg "routes:|deferReply:|group:|onUnknownRoute" src`

Before:

```diff
- routes: [{ path: "admin:clear", deferReply: { flags: "Ephemeral" }, handler: clearNotes }]
```

After:

```ts
import { SlashCommandModule } from "vimcord";
const command = new SlashCommandModule({
    builder: b => b.setName("notes").setDescription("Manages notes.")
        .addSubcommandGroup(g => g.setName("admin").setDescription("Admin tools")
            .addSubcommand(s => s.setName("clear").setDescription("Clears notes"))),
    subcommands: { "admin:clear": { deferReply: "ephemeral", async handler({ interaction }) { await interaction.editReply("Cleared."); } } }

```

Subcommands are keyed records for both slash and prefix commands. Restrictions are flat on each entry and apply after parent restrictions. A subcommand allowBots overrides the parent. Autocomplete and deferral may override the parent; false disables inherited deferral. Allowed deferral values are false, true, and "ephemeral". Unknown paths use execute when present, otherwise onBlocked unknownRoute. No execute/subcommand handler is an invalid module. Failed preparation never reaches the handler and produces no usage line.

Verify: `pnpm tsc --noEmit`; invoke every registered subcommand, including an unmatched path, and force a development deferral failure to check onError.

## Mongoose plugin 1 to 2

Apply the following connection, schema, and transaction changes together. The plugin guide is [published with the package](https://www.npmjs.com/package/@vimcord/plugin-mongoose).

### Mongoose connection options and lifecycle

Find: `rg "maxRetries|requireConnection|mongooseOptions|runMigrations|\.connect\(|\.disconnect\(|defineMigration" src`

Before:

```diff
- new MongoosePlugin({ uri, maxRetries: 5, requireConnection: false, strictQuery: true });
- await database.connect();
- await database.runMigrations();
```

After:

```ts
import { MongoosePlugin } from "@vimcord/plugin-mongoose";
const database = new MongoosePlugin({ connectOptions: { maxPoolSize: 10 } });
database.mongoose.set("strictQuery", true);
database.defineMigration("backfill-v2", async ({ mongoose }) => {
    await mongoose.connection.collection("records").updateMany({ active: { $exists: false } }, { $set: { active: true } });
});
```

Only uri and connectOptions remain. Use the plugin's isolated mongoose instance for Mongoose-wide settings before login. Initial connection always retries three times then throws. Public connect/disconnect/runMigrations are removed; login/destroy own them. ### Lazy models and lean reads

Find: `rg "leanByDefault|compileModel|InferHydratedDoc|CreateDocument|\.model|\.client|\.plugin" src`

Before:

```diff
- const Users = createMongoSchema("users", definition, { leanByDefault: false });
- Users.compileModel();
- const user = await Users.fetch(filter);
```

After:

```ts
import { createMongoSchema } from "@vimcord/plugin-mongoose";
const Users = createMongoSchema("users", { userId: { type: String, required: true } });
const user = await Users.fetch({ userId: USER_ID }, undefined, { lean: false });
```
